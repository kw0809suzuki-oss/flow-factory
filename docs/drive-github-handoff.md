# Drive ↔ GitHub Handoff

## Drive owns

- source material and provenance
- job objective
- observed / inferred / assumed separation
- boundary
- re-entry
- component registry and real-use evidence

## GitHub owns

- executable experiment code
- tests
- fixtures derived from permitted source material
- comparison scripts
- ablations
- versioned behavior

## Handoff into GitHub

A work item should include:

- source reference
- objective
- candidate relation
- measurable observable difference
- boundary
- expected return shape

## Return to Drive

Return:

- commit / artifact reference
- what was actually executed
- observed effect
- comparison/control result
- failure case
- boundary
- residual branch, if any
- re-entry

## Rule

GitHub does not promote a result to truth.
It produces executable evidence for the factory.
